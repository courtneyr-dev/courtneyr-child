## Deviations from the plan

### `cr-hero-photo` simplifications (D-4 deviation)

The live home page hero uses non-core blocks and a shortcode that don't fit a clean starting pattern:

1. **Removed `outermost/icon-block` (Spectra plugin)** — the Phase B rotating bg tokens already cover the visual rhythm in the homepage context. Re-add via Spectra if the user wants the arrow-circle accents back.
2. **Replaced `[newsletter_form]` shortcode** with paired CTA + outline buttons linking to `/newsletter/` and `/about/`. The pattern is meant as starting markup; the user inserts the form block-by-block when migrating.
3. **Image URL is root-relative** (`/wp-content/uploads/2023/05/cropped-courtney-pirate-jpeg.avif`) so it resolves on both staging and production. The user swaps the image after inserting.

Original markup preserved verbatim where possible: heading, bold subhead, and lead paragraph are exactly what's on the live home page.

### Stream item: glyph not SVG (D-6 confirmed)

`cr-stream-item` uses a typographic ✦ glyph instead of `<svg><use href="icons.svg#post-icon-blog">`. The icon-inject machinery (`inc/enqueue.php:174-198`) is wired and the sprite (`assets/svg/icons.svg`) exists, but rendering it in a Gutenberg pattern requires a custom block or `core/html`. Per plan, deferred to Phase E (stream as Query Loop variation).

### No pattern-bindings (D-5 confirmed)

None of the 9 patterns use WP 6.6 `metadata.bindings`. The existing `patterns/post-format-quote.php` uses bindings for IndieWeb post-format reuse — that's the right use case. Phase A patterns are insertable layouts users edit in place; bindings would add complexity without payoff.

### Specific gotchas to check

- **Button block styles**: WP's `wp-element-button` has its own background/color from `theme.json` `styles.elements.button`. If `is-style-cr-cta > .wp-block-button__link` doesn't override, may need to bump specificity (e.g. add `.wp-element-button` to the descendant selector). Inspect a CTA button in DevTools — confirm the `.cr-cta` ruleset wins.
- **Separator marker-bar**: `.wp-block-separator` defaults to `border-top` for the visible line. The `.cr-marker-bar` rule uses `background` + `border: 0`. The `hr.is-style-cr-marker-bar` selector qualifier should win specificity, but if the orange bar doesn't show, the cause is the `border-top` default — fix by adding `border-top: 0 !important` to the rule (the kit doesn't need it because `<hr class="cr-marker-bar">` doesn't have `.wp-block-separator`).
- **Pull quote rules**: `.wp-block-quote` has its own default border / padding from theme.json. If the cr-pull-quote rule loses, scope tighter: `blockquote.is-style-cr-pull-quote`.
